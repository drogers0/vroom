T23 Incremental Prefix Seeding — A/B Timing Benchmark
=====================================================

Date: 2026-08-19
Branch: feature/shipment-max-ride-time
Change: seed compute_cap_compliant_schedule (candidate overload) from committed
        route arrays at first_rank instead of re-simulating the full prefix.
        Equivalence shadow pass gated behind opt-in VROOM_ENGINE_SEED_SHADOW
        macro (default build unaffected; vroom's makefile ships asserts on,
        so tying the shadow to NDEBUG would have cost 10-20% in default builds).

Methodology
-----------
- 29 alpha2 constrained PDPTW instances (Li & Lim 100-task, TW-aware caps).
- Matched builds: BOTH binaries default makefile flags (-O3, asserts on,
  no shadow). Single-threaded (-t 1). 3 runs per instance, median.

Verification
------------
- Shadow build (VROOM_ENGINE_SEED_SHADOW): full unseeded engine re-run asserts
  identical decision, schedule, and break timings at every seeded call.
  29/29 alpha2 instances clean; harness 25/25 (release and shadow builds);
  feature suite 28/28 under shadow binary.
- Parity pre vs post (-t 1, computing_times excluded): 56/58 byte-identical
  (29 alpha2 + 29 base); the 2 flagged base instances are pre-existing rare
  run-to-run solver nondeterminism (pre binary alone produced both outputs
  across 5 runs on lc107; lc109 matched on re-run), not the seeding change.
- Alpha2 cap property check: 0 violations on all 29 instances.
